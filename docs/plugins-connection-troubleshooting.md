# Plugins 连接器与扩展下载排查

## ChatGPT 刷新报错或没有可用操作

Core、Desktop、Plugins 是三条不同的 MCP 通道。使用 OpenAI 隧道时，Core 已连接或 Desktop 可用，都不能证明 Plugins 已经发布。

在知行左下角打开 **设置 → 连接与扩展 → 连接器隧道**，在 Core、Desktop 下方填写 **Plugins 插件隧道 ID**。也可以从 **MCP／插件 → 配置插件连接** 直接定位到同一表单。配置自动保存，隧道 API Key 在同页安全保存；Plugins 的名称、说明、地址和状态也在同页的连接器信息中查看。

旧预览版 .8 的字段仍在插件页的“设置插件”弹窗中；新的统一入口需要使用包含本次修复的构建。

1. 检查外部 MCP 是否已安装、启用并提供工具。
2. 填入原来用于 Plugins 的独立隧道 ID；同一个工作区已有隧道时不必重复创建。
3. 保存后确认 Plugins 通道在线，再到原来的 ChatGPT 连接器详情里刷新。
4. 以 ChatGPT 实际显示工具列表为刷新成功依据；本地保存、启动浏览器或 Core 连通均不能替代这个结果。

保留不同安装目录和测试数据目录的配置隔离。测试版不会自动继承正式版的隧道与插件，配置缺失时应明确提示，不能自动切换到另一套服务。

账号配对连接的自动刷新尚未接入完整隔离流程。当前自动刷新开关只适用于旧式浏览器配对；账号连接需要在对应浏览器 Profile 的 ChatGPT 中手动处理。不要取消账号校验来绕过这一限制。

如果隧道在线后仍失败，继续核对对应工作区的管理员权限、应用的工具快照与服务端错误；不要连续刷新或先删除已有连接。[OpenAI 的连接器更新说明](https://help.openai.com/en/articles/12584461)区分了不同工作区的刷新、审批与重新发布流程。

## 扩展下载

Git 标签不是 GitHub Release 资产。使用预览版本号直接拼出 `/releases/download/<version>/...zip`，可能得到不存在的地址。

优先使用 **设置 → 连接与扩展 → 安装浏览器扩展**。软件从附带文件准备稳定的 `userData/extension` 目录，“复制安装路径”和“打开扩展文件夹”均由主进程解析同一路径；不要求扩展位于程序安装目录。Chrome／Edge 中仍需由用户开启开发者模式并“加载已解压的扩展程序”。复制出的路径用于文件夹选择窗口，不能粘贴到地址栏当成安装命令。

加载后不要移动或删除该目录。升级后从相同路径重新加载扩展。“准备／修复扩展文件夹”会检查实际内容，修复被误删或改坏的文件；失败保留明确错误，不宣称浏览器已安装或已配对。整个流程无需网络下载。完整包和已准备副本都缺失时会明确要求恢复同一版本，不会下载任意版本冒充配套扩展。

**更多扩展操作 → 保存内置扩展 ZIP** 仅用于备份，附带 LICENSE；取消不报告成功，写入失败显示错误。日常安装无需先保存 ZIP 再选择另一个路径。

2.1.0 标签的配套扩展另见 [GitHub 预发布下载](https://github.com/ChaiAnAai/chat-on-steroids-unlimited-codex/releases/tag/v2.1.0)。它使用协议 14，不适用于仍使用协议 13 的旧桌面版。该预发布不含新桌面安装器。
